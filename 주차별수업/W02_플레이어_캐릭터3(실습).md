# 2주차 실습 - 샘플로 캐릭터 바꿔보기

**수업 시간에 함께 따라 하는 문서입니다.** 그림은 준비해 두었으니 **바꾸는 절차를 손으로 한 번 해보는 것**이 목적입니다.

**그림 다섯 가지를 바꾸고, 장수를 늘리는 것과 소리 바꾸는 것까지 해봅니다** - 대기(IDLE) · 공격1 · 공격2 · 공격1 이펙트 · 공격2 이펙트 · 공격 소리. **그림은 전부 「장수가 달라졌을 때 무엇을 해야 하는가」** 하나를 다른 자리에서 반복하는 것입니다. 이걸 해보면 **나머지 동작은 집에서 혼자 할 수 있습니다.**

> **개념 설명은 [2주차 본문](<W02_플레이어_캐릭터1(기본).md>), 항목별 설명은 [Inspector 항목 설명](<W02_플레이어_캐릭터2(인스팩터).md>) 에 있습니다.** 이 문서는 **순서대로 따라 하는 대본**입니다.

---

## 0. 오늘 하는 것과 안 하는 것

**오늘 수업에서 하는 것**

| 순서 | 무엇을 | 장수 |
|---|---|---|
| 1 | **대기(IDLE)** | 4장 → **2장** → **3장** |
| 2 | **공격1 모션** | 4장 → **3장** |
| 3 | **공격2 모션** | 4장 → **3장** |
| 4 | **공격1 이펙트** | 4장 → **1장** |
| 5 | **공격2 이펙트** | 3장 → **2장** |
| 6 | **공격1·2 소리** | 파일 2개 교체 (장수와 무관) |

**오늘 안 하는 것**

| | 언제 하나 |
|---|---|
| 나머지 동작 (걷기·점프·대시·피격·사망 등) | **과제** - 집에서 |
| **본인이 그린 그림으로 바꾸기** | **과제** - 집에서 |
| 배경 테스트 씬에 반영 | **3주차** - 몬스터까지 만든 뒤 한 번에 |

> ★ **오늘은 `ActionTest` 씬만 봅니다.** 다른 씬을 열어보면 「왜 여긴 안 바뀌었지?」 하고 헷갈리기만 합니다. **주인공은 씬마다 따로 있어서** 지금 고친 것이 다른 씬에 자동으로 가지 않습니다. 그건 3주차에 몬스터까지 만든 뒤 한 번에 반영합니다.

> **샘플 그림은 연습용입니다. 이것을 과제로 내는 것이 아닙니다.**

## 1. 샘플 받기

**[샘플 파일 내려받기](https://github.com/hansung-game1/game-p-docs/raw/main/%EC%A3%BC%EC%B0%A8%EB%B3%84%EC%88%98%EC%97%85/files/W02_%EC%83%98%ED%94%8C_%EC%BA%90%EB%A6%AD%ED%84%B0.zip)** ← 누르면 바로 받아집니다 (약 590KB)

압축을 풀면 **`Art` 와 `Sound` 두 폴더**가 나옵니다. **들어가는 자리가 서로 다릅니다.**

**① `Art\` → `Assets\_Project\04_Art\StudentReplace\`**

```
Art\Player\idle_frames\                player_idle_01 ~ 02        (2장)
Art\Player\attack1_frames\             player_attack1_01 ~ 03     (3장)
Art\Player\attack2_frames\             player_attack2_01 ~ 03     (3장)
Art\Effects\AttackEffect01_frames\     effect_attack1_01          (1장)
Art\Effects\AttackEffect02_frames\     effect_attack2_01 ~ 02     (2장)
```

**`Art` 안쪽은 프로젝트의 그 폴더와 구조가 똑같습니다.**

**② `Sound\` → `Assets\_Project\06_Audio\SFX\Player\`**

```
Sound\player_attack1_swing.mp3         공격1 휘두르는 소리
Sound\player_attack2_swing.mp3         공격2 휘두르는 소리
```

> **소리는 그림과 다른 폴더로 갑니다.** `StudentReplace` 안에 넣으면 아무 일도 일어나지 않습니다. 소리는 **7번**에서 맨 마지막에 합니다.

> **한꺼번에 다 덮어쓰지 마세요.** 아래 단계에서 **하나씩** 넣습니다. 한 번에 다 넣으면 무엇 때문에 무슨 일이 생기는지 안 보입니다.

### ★ 시작 전에 - 파일 확장자가 보이는지 확인하세요

**`.png` · `.mp3` 처럼 이름 뒤에 붙는 것을 확장자라고 합니다.** Windows도 Mac도 **이것을 숨기는 것이 기본 설정**이라, 그냥 두면 오늘 **7번(소리)에서 막힙니다.**

그 자리에서 이런 두 파일을 구별해야 하는데,

```
player_attack1_swing.ogg      ← 지울 것
player_attack1_swing.mp3      ← 넣을 것
```

**확장자가 숨겨져 있으면 화면에 둘 다 `player_attack1_swing` 으로 똑같이 보입니다.** 어느 것을 지워야 하는지 알 수 없습니다.

| | 켜는 법 |
|---|---|
| **Windows** | 탐색기 상단 **`보기`** → **`표시`** → **`파일 확장명`** 체크 |
| **Mac** | **`Finder`** 메뉴 → **`설정…`**(옛 버전은 `환경설정…`) → **`고급`** → **`모든 파일 확장자 보기`** 체크 |

**한 번만 켜두면 계속 유지됩니다.** 지금 켜두세요.

### Mac을 쓰신다면 - 이름만 다릅니다

**하는 일은 똑같습니다.** 이 문서는 Windows 기준으로 쓰여 있어서 **말이 몇 개 다를 뿐입니다.**

| 이 문서에서 | Mac에서는 |
|---|---|
| **탐색기** | **`Finder`** |
| `Player\idle_frames\` | `Player/idle_frames/` - **빗금 방향이 반대** |
| **`Ctrl`** + `S` | **`Cmd`** + `S` |

> **Unity 화면 안은 완전히 같습니다.** 폴더를 열고 파일을 옮기는 것만 Finder에서 합니다.

## 2. 대기(IDLE) - 기본 순서를 익힙니다 (4장 → 2장 → 3장)

**가장 단순한 동작부터 합니다.** 대기 모션에는 공격 판정도 이펙트도 없어서 **「파일과 배열은 별개다」** 하나만 배우면 됩니다.

### 2-1. 파일을 덮어씁니다

탐색기에서 `Player\idle_frames\` 를 열고, 샘플의 **`player_idle_01.png`, `player_idle_02.png` 두 장**을 덮어씁니다.

**폴더 안은 이렇게 됩니다.**

| | |
|---|---|
| `player_idle_01` · `02` | **새 그림으로 바뀜** |
| `player_idle_03` · `04` | **옛 그림이 그대로 남아 있음** |

**아직 지우지 마세요.** 다음에 무슨 일이 생기는지 먼저 봅니다.

### 2-2. 확인 - 옛 그림이 섞여 나옵니다

`ActionTest` 씬에서 **Play**를 누르고 가만히 둡니다.

**새 그림 2장 다음에 옛 그림 2장이 이어서 나옵니다. 고장이 아닙니다.**

| 그림 파일 | 2장으로 바뀜 |
|---|---|
| **Inspector의 배열** | **아직 4칸 그대로** |

**Unity는 「몇 번째 그림을 쓸지」를 배열로 기억합니다.** 파일을 덮어써도 칸 수는 그대로라서, **3·4번 칸이 아직 남아 있는 옛 그림을 가리키고 있는 것**입니다.

**Play를 끕니다.** 값은 항상 Play를 끈 상태에서 고칩니다.

### 2-3. 남은 파일을 지웁니다

**탐색기에서** `player_idle_03.png`, `player_idle_04.png` 를 지웁니다.

> **`.meta` 파일이 같이 보이면 그것도 함께 지웁니다.** 짝이 맞아야 합니다. (탐색기 설정에 따라 안 보일 수도 있는데, 안 보이면 그냥 두세요 - Unity가 정리합니다.)

**Unity로 돌아오면 Inspector의 3·4번 칸이 `None`으로 바뀝니다.** 무엇을 지워야 하는지 눈에 보이는 상태가 된 것입니다.

### 2-4. 배열을 줄입니다

1. `Hierarchy`에서 **`Player_ActionTest`** 클릭
2. `Inspector`의 **`Sprites`** 묶음에서 **`Idle Frames`** 를 찾습니다
3. 배열 이름 **오른쪽 끝 숫자**를 **`4` → `2`** 로 바꿉니다

> `None`이 된 칸이 사라집니다. 자세한 조작은 [Inspector 항목 설명 2절](<W02_플레이어_캐릭터2(인스팩터).md>)의 「배열을 다루는 법」에 있습니다.

### 2-5. 다시 확인합니다

**Play → 이제 2장만 반복됩니다.** 대기 동작이 짧아진 것도 느껴집니다 - **재생 속도(초당 6장)는 고정이라 장수가 줄면 한 바퀴가 짧아집니다.**

### 2-6. 이번엔 반대로 - 2장에서 3장으로 늘려봅니다

**과제에서는 줄이는 것보다 늘리는 일이 더 많습니다.** 같은 폴더에서 한 번 해봅니다.

**1) 파일을 하나 더 만듭니다**

탐색기에서 `player_idle_02.png` 를 **복사해서 `player_idle_03.png`** 로 이름을 바꿉니다.

> **연습이라 같은 그림을 복사해 씁니다.** 과제에서는 여기에 새로 그린 그림이 들어갑니다.

**Unity로 돌아오면 자동으로 읽어들이고 `.meta` 파일도 만들어집니다.** `Console` 창에 이런 줄이 뜹니다.

```
[player_idle_03.png] 새 그림이라 같은 폴더의 «player_idle_01.png» 설정을 물려받았습니다
```

> **이 줄이 뜨는 것이 중요합니다.** 새로 만든 그림은 원래 「캐릭터가 발밑에 서는 기준」을 모릅니다. 그대로 두면 **그 프레임만 화면 아래로 내려앉습니다.** 프로젝트가 옆 그림의 설정을 자동으로 물려주도록 해두었습니다.

**2) 배열을 3으로 늘립니다**

`Idle Frames` 오른쪽 끝 숫자를 **`2` → `3`** 으로.

**3) ★ 새 칸이 앞 칸과 똑같이 나옵니다**

칸은 3개가 됐는데 **`Element 1`과 `Element 2`가 둘 다 `player_idle_02`** 입니다.

**Unity가 마지막 칸을 복제해서 새 칸을 만들기 때문입니다.** 빈 칸으로 두지 않습니다. **여기서 멈추면 같은 그림이 두 번 나옵니다.**

**4) 새 칸에 새 그림을 넣습니다**

1. 아래쪽 **`Project`** 창에서 `Assets > _Project > 04_Art > StudentReplace > Player > idle_frames` 로 들어갑니다
2. **`player_idle_03`** 을 `Inspector`의 **`Element 2`** 칸으로 **끌어다 놓습니다**

> ⚠️ **`Element`는 0부터 셉니다.** 3장이면 `Element 0` · `1` · `2` 이고, **세 번째 칸은 `Element 2`** 입니다. (판정 프레임 숫자는 1부터 세니 헷갈리지 마세요 - 뒤에서 다시 나옵니다.)

**5) Play로 확인합니다**

3장이 순서대로 반복되면 성공입니다.

### ★ 오늘의 순서 - 앞으로 계속 반복합니다

**장수를 줄일 때**

| | |
|---|---|
| **①** | 파일 **덮어쓰기** |
| **②** | Play로 **확인** → 옛 그림이 섞여 나옴 |
| **③** | 남은 **파일 지우기** → 배열 칸이 `None`이 됨 |
| **④** | **배열 줄이기** |
| **⑤** | Play로 **확인** |

**장수를 늘릴 때 - 순서가 반대이고, 한 단계가 더 있습니다**

| | |
|---|---|
| **①** | 파일 **만들기** (복사하거나 새로 그려서) |
| **②** | **배열 늘리기** |
| **③** | ★ **새 칸에 새 그림 끌어다 넣기** ← 빠뜨리면 앞 그림이 두 번 나옵니다 |
| **④** | Play로 **확인** |

> **줄일 때는 파일이 먼저, 늘릴 때는 배열이 먼저**라고 외우면 편합니다. **줄일 때는 지운 자리가 `None`으로 보이지만, 늘릴 때는 빈 칸이 아니라 앞 그림의 복제가 들어오기 때문에** 눈에 덜 띕니다.

**공격 동작에는 여기에 판정 프레임 확인이 더 붙습니다.** 다음에서 봅니다.

## 3. 공격1 모션 - 판정 프레임이 붙습니다 (4장 → 3장)

**②~④까지는 IDLE과 똑같습니다.**

1. `Player\attack1_frames\` 에 샘플 **3장**을 덮어씁니다
2. Play → **4번째에 옛 그림이 섞여 나옵니다**
3. `player_attack1_04.png` 를 지웁니다
4. `Attack 1 Frames` 배열을 **`4` → `3`** 으로

### 3-1. 그런데 공격이 늦게 맞습니다

**몬스터 쪽으로 가서 `J` 로 공격해봅니다.**

**칼을 다 휘두르고 내린 뒤에야 몬스터가 맞습니다.** 에러는 하나도 안 뜹니다.

| | |
|---|---|
| `Attack 1 Damage Frame` | **`3`** - 3번째 그림에서 판정 |
| 그런데 지금 공격은 | **3장**뿐 → 3번째가 **마지막 그림** |
| 실제로 베는 그림은 | **2번째** |

**숫자는 그대로인데 뜻이 달라진 것입니다.** 4장일 때의 `3`과 3장일 때의 `3`은 다른 자리입니다.

### 3-2. 판정 프레임을 확인합니다 - 셋 중 둘을 고칩니다

**「몇 번째 그림에서 일이 벌어지는가」를 정하는 숫자가 세 개 있습니다.** 장수를 바꿨으면 **셋 다 확인**합니다.

`Inspector`의 **`Effect Placement`** 묶음을 찾아 아래로 스크롤합니다. **소리 항목만 조금 더 아래 `SFX` 묶음에 있습니다.**

| 항목 | 무엇이 일어나는 순간인가 | 이번에는 |
|---|---|---|
| **`Attack 1 Damage Frame`** | 몬스터가 **맞는** 순간 | `3` → **`2`** |
| **`Attack 1 Effect Start Frame`** | 검격 **이펙트**가 뜨는 순간 | `3` → **`2`** |
| **`Attack 1 Swing Frame`** | 휘두르는 **소리**가 나는 순간 | **`1` - 그대로 둡니다** |

**앞의 둘은 `3`이라 3장짜리에서 마지막 그림을 가리키고 있었습니다.** 그래서 고쳤습니다.

**`Swing Frame`은 `1`이라 이번엔 안 고쳐도 됩니다.** 1번째 그림은 3장에서도 그대로 있으니까요.

> ★ **그래도 확인은 해야 합니다.** 공격을 **1장으로** 줄였다면 이 숫자도 봐야 했을 것이고, 무엇보다 **「소리 담당 숫자가 따로 있다」는 걸 모르면 나중에 소리만 어긋났을 때 원인을 못 찾습니다.** 그림도 이펙트도 멀쩡한데 소리만 이상한 상황이 됩니다.

**Play → 이제 베는 순간에 이펙트가 뜨고 몬스터가 맞습니다.**

> **이 숫자들은 1부터 셉니다.** 배열의 `Element`는 0부터인데 여기는 1부터입니다. [Inspector 항목 설명 4-2절](<W02_플레이어_캐릭터2(인스팩터).md>)

## 4. 공격2 모션 - 이번엔 혼자 해봅니다 (4장 → 3장)

**3번과 완전히 같습니다.** 폴더와 숫자만 다릅니다.

**먼저 스스로 해보세요.**

- 폴더: `Player\attack2_frames\` - 샘플 **3장**
- 배열: `Attack 2 Frames`
- 판정 숫자 **셋**: `Attack 2 Damage Frame` · `Attack 2 Effect Start Frame` · `Attack 2 Swing Frame`

**공격2는 `J`를 두 번 눌러야 나옵니다** (1타 → 2타 콤보).

### 정답

| 항목 | 바꿀 값 |
|---|---|
| `Attack 2 Frames` | `4` → **`3`** |
| **`Attack 2 Damage Frame`** | `2` → **`1`** |
| **`Attack 2 Effect Start Frame`** | `2` → **`1`** |
| **`Attack 2 Swing Frame`** | **`1` - 그대로 둡니다** |

> **공격1은 `3 → 2`, 공격2는 `2 → 1`입니다.** 숫자가 다른 이유는 **원래 값이 달랐기 때문**입니다 - 동작마다 실제로 베는 그림이 몇 번째인지가 다릅니다. **정해진 공식이 있는 게 아니라, 내 그림을 보고 정하는 것입니다.**

> **`Swing Frame`은 둘 다 `1`이라 이번 실습에서는 손댈 일이 없습니다.** 그래도 **셋을 다 열어보는 것**이 오늘 익힐 습관입니다.

## 5. 공격1 이펙트 - 위치와 크기 (4장 → 1장)

**이펙트 그림은 주인공 몸과 다른 폴더에 있습니다.**

```
Assets\_Project\04_Art\StudentReplace\Effects\AttackEffect01_frames\
```

1. 샘플 **1장**(`effect_attack1_01.png`)을 덮어씁니다
2. Play → 옛 그림이 섞여 나옵니다
3. `effect_attack1_02 ~ 04` 를 지웁니다
4. `Inspector`의 **`Effects`** 묶음에서 **`Attack Effect 1 Frames`** 를 **`4` → `1`** 로

> ⚠️ **`Attack Effect`(맨 위)와 `Attack Effect 1 Frames`(아래)는 다른 것입니다.** 위의 `Attack Effect`는 **이펙트를 그려줄 오브젝트를 연결해둔 칸**이라 **비우면 이펙트가 아예 안 나옵니다.** 건드리지 마세요. 우리가 바꿀 것은 **`Frames`가 붙은 쪽**입니다.

### 5-1. 이펙트가 엉뚱한 자리에 뜹니다

**샘플 검격은 원본보다 작고, 캐릭터의 팔 길이도 다릅니다.** 그래서 위치와 크기를 맞춰줘야 합니다.

`Inspector`의 **`Effect Placement`** 묶음 맨 위입니다.

| 항목 | 기본값 | 바꿀 값 |
|---|---|---|
| **`Attack 1 Effect Offset`** | (2, 3.2, 0) | **(1.7, 2.2, 0)** |
| **`Attack 1 Effect Scale`** | (1.5, 1.5, 1) | **(0.7, 0.7, 1)** |

> **`Z`는 건드리지 않습니다.**

**Play로 확인하면서 조금씩 바꿔보세요.** 위 값은 이 샘플에 맞춘 것이고, **본인 그림에서는 다른 값이 됩니다.**

> ★ **원본과 많이 다르게 그릴수록 고칠 것이 많아집니다.** 팔이 길어지면 위치를 밀어야 하고, 검격이 커지면 크기를 줄여야 합니다. **러프 단계에서 원본 비율을 크게 벗어나지 않는 것이 나중에 편한 이유**가 이것입니다.

## 7. 공격 소리 - 여기서는 덮어쓰기가 안 됩니다

**여기까지는 그림만 바꿨습니다. 소리도 바꿔봅니다.** 마지막이고, 짧습니다.

### 7-1. 소리는 다른 폴더에 있습니다

```
Assets\_Project\06_Audio\SFX\Player\
```

열어보면 이렇게 들어 있습니다.

```
player_attack1_swing.ogg      ← 공격1 휘두르는 소리
player_attack2_swing.ogg      ← 공격2 휘두르는 소리
player_jump.wav  player_dash.wav  player_hit.wav  ...
```

**`04_Art\StudentReplace\` 가 아닙니다.** 그림과 소리는 사는 곳이 다릅니다.

> 이 폴더의 `readme.txt` 에 **파일명 목록**이 전부 적혀 있습니다. 과제로 나머지 소리를 넣을 때 그것을 보면 됩니다.

### 7-2. 넣고, 옛것을 지웁니다

프로젝트에 있는 것은 **`.ogg`**, 샘플은 **`.mp3`** 입니다. **이름은 같은데 확장자가 다릅니다.** 지금까지는 이름도 확장자도 같아서 그냥 덮어썼지만, 이건 덮어쓰기가 안 됩니다.

1. **탐색기에서** `Sound\` 의 **mp3 2개**를 위 폴더에 **넣습니다** (덮어쓰기가 아니라 그냥 추가됩니다)
2. **원래 있던 `.ogg` 2개를 지웁니다** - `player_attack1_swing.ogg`, `player_attack2_swing.ogg`

> ⚠️ **두 파일이 화면에 똑같은 이름으로 보인다면 확장자가 숨겨져 있는 것입니다.** 1번의 **「시작 전에 - 파일 확장자가 보이는지 확인하세요」** 로 돌아가서 켜고 오세요. **켜지 않으면 어느 것을 지워야 하는지 알 수 없습니다.**

> **`.meta` 파일이 같이 보이면 그것도 함께 지웁니다.** 2-3번과 같습니다.

> **`.ogg`를 안 지우면 어떻게 되나?** 같은 이름이 둘이 되어 **Unity가 어느 쪽인지 모릅니다.** Console에 경고가 뜨고 알파벳순 첫 번째가 쓰입니다. 우연히 `.mp3`가 먼저라 소리는 나지만 **경고는 계속 남습니다.** 지우세요.

> **소리는 확장자가 자유입니다** - `wav` · `mp3` · `ogg` 다 됩니다. **이름만 정확하면** 인식됩니다. 그림에는 없는 규칙입니다.

### 7-3. 다시 연결합니다

**파일만 바꿔서는 소리가 안 납니다.** 그림은 덮어쓰기라 자리가 그대로였지만, 소리는 **파일이 새로 생긴 것**이라 주인공은 아직 사라진 옛 파일을 보고 있습니다.

1. **`Ctrl+S`** 로 먼저 씬을 저장합니다
2. **`Tools` > `Class Template` > `Wire Player SFX Clips`**

> **이 버튼을 누르면 화면이 다른 씬으로 넘어갑니다. 정상입니다.** 주인공이 있는 씬을 차례로 열어서 소리만 연결하고 저장하기 때문입니다. 끝나면 **`ActionTest` 씬을 다시 여세요.** (3주차에 할 「배경 씬에 반영」과는 다른 것입니다 - 이건 소리만 건드립니다.)

### 7-4. 확인합니다

**Play → 공격 → 소리가 바뀌어 있습니다.**

**소리가 나는 시점은 3-2번에서 본 그 값입니다.**

| 항목 | 무엇을 정하는가 |
|---|---|
| `Attack 1 Swing Frame` | 몇 번째 그림에서 소리가 나는가 |
| `Attack 2 Swing Frame` | 〃 |

**시간이 남으면** `Attack 1 Swing Frame` 을 **`1` → `3`** 으로 바꿔서 Play 해보세요. 소리가 늦게 납니다. **확인했으면 `1`로 되돌립니다.**
