## 3. 배경 완성하기

### 3-1. ★ 배경은 "뒤로 물러나야" 합니다

초보자가 배경에서 가장 많이 하는 실수는 **배경을 너무 잘 그리는 것**입니다.

배경이 캐릭터만큼 진하고 선명하면, 플레이어는 **자기 캐릭터가 어디 있는지 못 찾습니다.** 액션 게임에서 이건 치명적입니다.

| | 캐릭터 | 배경 |
|---|---|---|
| 채도 | **높게** | 낮게 |
| 명암 대비 | **강하게** | 약하게 |
| 디테일 | 있어도 됨 | **덩어리로 단순하게** |
| 선 | 뚜렷하게 | 흐리게 또는 없이 |

> **확인법**: 게임 화면을 캡처해서 **흑백으로 변환**해보세요. 캐릭터가 배경에서 튀어나와 보이면 합격입니다. 뭉개져 보이면 배경의 대비를 더 낮춰야 합니다.

### 3-2. 공기원근 - 5겹의 깊이를 만드는 것

```
bg1 (가장 앞)  →  진하고, 대비 강하고, 어둡게
bg2            →  ↓
bg3            →  ↓ 점점 연하게, 점점 하늘색에 가깝게
bg4            →  ↓
bg5 (하늘)     →  가장 연하고 대비 약하게
```

> **엔진이 자동으로 흐리게 해주지 않습니다.** 이 단계 차이를 **그림 자체에 직접 그려 넣어야** 합니다. 5겹을 아무리 잘 그려도 명도가 다 비슷하면 평면으로 보입니다.

**실전 요령**: 모든 레이어를 다 그린 뒤, 뒤쪽 레이어일수록 하늘색 계열 레이어를 오버레이로 얹고 불투명도를 단계적으로 높이면 한 번에 정리됩니다.

### 3-3. 바닥 - 규격 재확인 ★

| 항목 | 규격 |
|---|---|
| 파일명 | `ground1.png` ~ `ground7.png` (그 이상도 가능) |
| 크기 | **1920 x 1080px** (화면 전체 크기) |
| 지면 표면 위치 | **아래에서 200px** |
| 그 위쪽 | **전부 투명** |

> ★ **바닥은 캐릭터보다 "앞"에 그려집니다.** 200px 선보다 위쪽을 불투명하게 칠하면 **캐릭터 다리가 가려집니다.**
>
> 완성 단계에서는 이걸 **역이용**하세요. 지면 앞쪽에 낮은 풀·돌·난간·안개를 그려두면 캐릭터가 그 뒤로 지나가면서 자연스러운 깊이감(전경 레이어)이 생깁니다. 완성도가 크게 올라가는 기법입니다.

### 3-4. 이음새 - 완성 단계에서 반드시 확인

배경과 바닥은 좌우로 계속 반복됩니다. **러프에서는 티가 안 나던 이음새가 채색 후에 확 드러납니다.**

- 좌우 끝의 명도·색이 이어지는지
- 특징적인 형태(큰 나무, 간판)가 반복될 때 눈에 띄지 않는지
- **Play해서 오른쪽 끝까지 계속 이동하며** 확인하세요

### 3-5. 반영

```
Tools > Class Template > Apply Real Stage Art
```

`BackgroundTest` 씬을 연 상태에서 실행. **안전하게 반복 실행 가능**합니다.

> 파일명·개수를 그대로 두고 덮어썼다면 자동 반영되지만, 배경은 확실하게 하기 위해 한 번 실행해두는 것을 권장합니다.

## 4. UI 완성하기

### 4-1. UI는 "세트"로 완성합니다

버튼 하나씩 완성하지 말고, **같은 종류를 한꺼번에** 작업하세요.

- 버튼 전부(타이틀 5종 + 일시정지 6종 + 사망 3종 = 14종 × 3상태)는 **같은 템플릿**에서 출발
- 팝업 3종도 같은 프레임 디자인
- HP 바, 게이지도 같은 언어

> **작업 요령**: 버튼 하나를 완성한 뒤 그것을 템플릿으로 삼아 글자와 아이콘만 바꾸세요. 14종을 각각 다르게 디자인하면 시간도 오래 걸리고 통일성도 깨집니다.

### 4-2. 규격 재확인 ★ 완성하면서 크기가 틀어지기 쉽습니다

| 대상 | 크기 |
|---|---|
| 모든 메뉴 버튼 (타이틀/일시정지/사망) | **307 x 82px** |
| 팝업 배경 3종 | **602 x 715px** |
| 설정 저장 버튼 | 241 x 80px |
| 슬라이더 홈 / 손잡이 | 258x15 / 18x53px |
| 톱니 버튼 | 122 x 122px |
| 사망 일러스트 | 700 x 499px |
| 시작/클리어 배너 | 580 x 330px |
| HP 배경판 / HP 칸 / 게이지 | 591x155 / 35x35 / 326x66px |
| 컷신 버튼 | 214 x 87px |
| 모바일 조이스틱 / 버튼 | 331x331 / 222x222px |
| 타이틀 배경·모션·컷신 장면 | 1920 x 1080px |

> 크기가 달라졌으면 Unity에서 그 오브젝트 선택 → `Inspector`의 `Image` → **`Set Native Size`** 로 복구할 수 있습니다 (위치는 안 바뀝니다).

### 4-3. 팝업 안 글씨 - 실제 화면에서 읽히는지 확인 ★

`popup_controls` / `popup_settings` / `popup_credits` 는 **602x715px 그림 안에 글자를 직접 그려 넣습니다.**

이 팝업은 1920x1080 화면 안에 뜨므로 **화면의 1/3 정도 크기**로 보입니다. 포토샵에서 읽히던 글씨가 게임에서는 안 읽히는 경우가 많습니다.

- **반드시 Unity에서 Play해서 실제 크기로 확인**하세요
- 크레딧에는 **본인 학번·이름 + 사용한 사운드/폰트 출처**를 꼭 넣으세요

### 4-4. 사망 화면 일러스트

`deathcut.png` (700x499px)는 이 게임에서 학생이 그리는 **몇 안 되는 일러스트**입니다. 플레이어가 죽을 때마다 보게 되므로 인상에 강하게 남습니다. 시간을 들일 가치가 있습니다.

### 4-5. 반영

- 파일명/개수 그대로 덮어쓰기 → **자동 반영**
- `title_motion` 프레임 수를 바꿨다면 →

```
Tools > Class Template > Refresh Title Motion Frames
```

- HUD/시스템을 다시 정리하고 싶다면 → **`BackgroundTest` 씬을 열고**

```
Tools > Class Template > Add All HUD & Systems To Background Test Scene
```

> ⚠️ Preview 토글을 켰다면 **반드시 끄고 저장**하세요.
>
> ```
> Tools > Class Template > Toggle Pause Menu Preview
> Tools > Class Template > Toggle Stage Clear Panel Preview
> Tools > Class Template > Title Preview > ...
> ```

## 5. 컷신 완성하기

### 5-1. 인트로와 엔딩의 톤을 맞추세요

- 같은 그림체, 같은 구도 언어, 같은 팔레트
- 인트로에서 던진 문제가 엔딩에서 해결되는 구조

### 5-2. 규격 재확인

| 항목 | 인트로 | 엔딩 |
|---|---|---|
| 파일명 | `cutscene01.png` ... | **`ending01.png`** ... |
| 크기 | 1920 x 1080px | 1920 x 1080px |
| 버튼 | 214x87 (next/prev/skip) | 214x87 (같은 파일 복사) |
| 갱신 명령 | `Tools > Class Template >`<br>`Refresh Intro Cutscene Slides` | `Tools > Class Template >`<br>`Refresh Ending Cutscene Slides` |

### 5-3. 장면 수를 늘렸다면

**반드시 아래를 실행하세요. 안 하면 새 장면이 안 나옵니다.**

```
Tools > Class Template > Refresh Intro Cutscene Slides
Tools > Class Template > Refresh Ending Cutscene Slides
```

**인트로를 늘렸으면 위쪽, 엔딩을 늘렸으면 아래쪽**입니다. 둘 다 늘렸으면 둘 다 실행하세요.

### 5-4. 동영상으로 바꾸고 싶다면 (선택)

같은 번호 자리에 확장자만 `.mp4`(H.264, 1920x1080). 파일명 접두사(`cutscene` / `ending`)는 그대로 지켜야 합니다.

> ⚠️ **GitHub는 파일 하나가 100MB를 넘으면 거부합니다.** 영상은 압축해서 넣으세요.

## 6. 확인하기 - 전체 톤 점검

이번 주는 **개별 리소스가 아니라 "화면 전체"** 를 봐야 합니다.

### 스크린샷을 찍어서 나란히 놓고 비교하세요

다음 6개 화면을 캡처해서 한 화면에 나란히 놓아보세요:

1. 타이틀 화면
2. 인트로 컷신 한 장면
3. 스테이지 전투 중
4. 일시정지 메뉴가 열린 상태
5. 사망 화면
6. 엔딩 컷신 마지막 장면

| 점검 질문 | |
|---|---|
| **6장이 같은 게임처럼 보이나** | 그림체·팔레트·선 굵기 |
| 어느 한 화면만 튀지 않나 | |
| UI 버튼 디자인이 화면마다 통일되어 있나 | |
| 캐릭터가 배경에서 잘 보이나 | |
| 전체 색조가 한 방향인가 | |

> **이 6장이 하나의 게임으로 보이면 "전체 분위기와 통일성" 항목은 확보한 것입니다.** 이 6장이 그대로 발표 자료와 포트폴리오가 됩니다.

### 게임으로도 확인

`Title` 씬에서 Play → 엔딩까지 한 바퀴.

| 확인 항목 | |
|---|---|
| 배경 이음새가 티 나지 않나 | 좌우로 길게 이동 |
| 바닥이 캐릭터 다리를 가리지 않나 | |
| 패럴렉스 깊이감이 살아 있나 | |
| 팝업 글씨가 읽히나 | |
| UI 크기가 틀어지지 않았나 | |
| Preview 토글이 꺼진 상태로 시작하나 | |

### 여유가 되면 - 중간 빌드

**PC 빌드를 한 번 더 만들어보세요.** 에디터와 빌드는 색감·해상도가 미묘하게 다를 수 있고, 무엇보다 **14주차 최종 빌드에서 처음 문제를 발견하는 상황을 피할 수 있습니다.**

## 과제 (13주차)

### 무엇을 해오나

**기존 러프 컨셉을 토대로 배경·UI·컷신을 완성·보완**

- 우선순위대로 (배경 → 바닥 → 타이틀 → HUD/메뉴 → 컷신)
- **전체 톤 통일**에 신경 쓸 것

### 제출

네이버 카페 업로드 - 제목 `2D게임제작_13주차_123456김한성`

- [ ] **진행본 스크린샷**
  - ★ 위에서 만든 **대표 화면 6장**을 넣으면 그대로 발표 자료가 됩니다
- [ ] **진행본 영상** (길이 자유, 30초 내외 권장)

### 제출 전 체크리스트

- [ ] 배경 5겹의 **명도 단계 차이**가 보이는가
- [ ] 캐릭터가 배경에서 분리되어 보이는가 (흑백 변환으로 확인)
- [ ] 배경/바닥 **이음새**가 티 나지 않는가
- [ ] 바닥 그림이 캐릭터 다리를 가리지 않는가
- [ ] UI 픽셀 규격이 전부 유지되고 있는가
- [ ] **팝업 안 글씨가 실제 화면에서 읽히는가**
- [ ] 크레딧에 본인 정보와 출처를 적었는가
- [ ] 컷신 장면 수를 바꿨다면 `Tools > Class Template > Refresh Intro/Ending Cutscene Slides` 를 실행했는가
- [ ] **Preview 토글을 전부 끄고 저장했는가**
- [ ] 6개 대표 화면이 하나의 게임처럼 보이는가
- [ ] Ctrl+S → Commit → **Push까지 완료**했는가
