# 12주차 - 리소스 완성 1 : 캐릭터 · 몬스터 · 이펙트

**이번 주 목표**: 2·3주차에 러프로 만든 **캐릭터와 몬스터를 완성본으로** 끌어올린다.

---

## 1. 지금부터가 "완성 단계"입니다

2~9주차에 러프로 게임 전체를 완성했고, 10주차에 빌드로 확인했고, 11주차에 소리까지 넣었습니다.

**이제 남은 3주(12·13·14)는 그 위에 그림을 채우는 시간입니다.**

```
러프 단계 (2~9주차)              완성 단계 (12~14주차)
─────────────────────           ─────────────────────
구조를 확정한다             →    질을 끌어올린다
"돌아가는가?"                    "좋아 보이는가?"
컬러링 없음                      채색 · 명암 · 디테일 · 마감
```

> **러프를 버리고 새로 그리지 마세요.** 러프는 이미 게임 안에서 "동작이 맞는 것"이 검증된 상태입니다. 그 위에 채색하는 것이 가장 빠르고 안전합니다. 새로 그리면 타이밍·크기·기준점을 처음부터 다시 맞춰야 합니다.

## 4. 완성 작업 지침

### 4-1. 게임 화면에서 실제로 보이는 크기를 기준으로 작업하세요 ★

가장 많이 하는 실수입니다.

- 캐릭터 캔버스는 500x500px이지만, **1920x1080 화면 안에서 캐릭터는 화면 높이의 1/4~1/3 정도**로 보입니다
- 포토샵에서 100% 확대로 보며 넣은 얼굴 디테일, 옷 무늬, 가는 선은 **게임 화면에서 거의 안 보입니다**
- **반대로 실루엣, 큰 명암 덩어리, 색 대비는 아주 잘 보입니다**

> **작업 요령**: 그리는 중간중간 **캔버스를 25~33% 축소해서 보세요.** 그 크기에서 형태가 읽히면 게임에서도 읽힙니다. 안 읽히면 디테일이 아니라 **덩어리와 대비**를 손봐야 합니다.
>
> 더 확실한 방법: **파일을 저장하고 Unity에서 Play해서 실제 화면에서 확인**하는 것입니다. 이게 진짜 기준입니다.

### 4-2. 배경에서 캐릭터가 분리되어 보여야 합니다

액션 게임에서 가장 중요한 것은 **"내가 어디 있는지 즉시 보이는 것"** 입니다.

- 플레이어는 **배경보다 채도·명도 대비를 높게**
- 몬스터도 배경에 묻히면 안 됩니다
- 배경(13주차)은 반대로 **대비를 낮춰서** 뒤로 물러나게 만듭니다

> 확인법: 완성한 화면을 **흑백으로 바꿔서** 보세요. 흑백에서도 캐릭터와 배경이 구분되면 합격입니다.

### 4-3. 프레임 간 일관성

한 동작의 프레임들 사이에서 **색·명암·굵기가 흔들리면 깜빡이는 것처럼 보입니다.**

- 채색은 **프레임별로 따로** 하지 말고, **한 동작 전체를 같은 팔레트/레이어 구조로** 작업하세요
- 색을 정할 때 **팔레트를 먼저 확정**하고 12개 동작 전부에 같은 팔레트를 쓰세요

### 4-4. 몬스터 3종을 서로 구분되게

- 실루엣이 다르고
- **주조색(메인 컬러)이 달라야** 합니다
- 플레이어와도 색이 겹치면 안 됩니다

> 예: 플레이어 = 파랑 계열, A = 회색/갈색, B = 붉은색, C = 보라/초록 — 이런 식으로 팔레트를 나눠두면 화면이 정리됩니다.

### 4-5. 이펙트 - 타격감의 핵심

폴더: `Assets/_Project/04_Art/StudentReplace/Effects/`

| 폴더 | 짝지어지는 플레이어 동작 |
|---|---|
| `AttackEffect01_frames` | 기본 공격 1타 |
| `AttackEffect02_frames` | 기본 공격 2타 |
| `JumpAttackEffect_frames` | 공중 공격 |
| `SpecialChargeEffect_frames` | 필살기 차지 중 |
| `SpecialLaser_frames` | 필살기 - 레이저 |
| `SpecialGroundBurst_frames` | 필살기 - 바닥 폭발 |

파일명:
```
effect_attack1_01.png / effect_attack2_01.png / effect_jump_attack_01.png /
effect_special_charge_01.png / effect_special_laser_01.png / effect_special_ground_burst_01.png
```

**규격**: PNG 투명, **캔버스 크기 자유**, **정가운데 기준**, 원래 파일과 **비슷한 크기 비율** 권장.

> **이펙트가 타격감을 만듭니다.** 밝게, 짧게, 빠르게가 원칙입니다. 첫 프레임이 가장 밝고 크게, 이후 빠르게 사라지는 구성이 잘 먹힙니다. 3~5장이면 충분합니다.

## 5. Unity에 반영하기

### 파일명과 개수를 그대로 두고 덮어쓰는 경우 ★ 가장 편한 방법

**파일을 덮어쓰기만 하면 끝입니다.** Unity가 자동으로 다시 읽고, 모든 씬에 반영됩니다. **아무 명령도 실행할 필요가 없습니다.**

> **이번 주 작업은 되도록 이 방식으로 하세요.** 러프와 같은 파일명·같은 장수로 완성본을 만들면, 폴더에 덮어쓰는 것만으로 게임 전체가 갱신됩니다.

### 프레임 수를 늘리는 경우 (완성하면서 동작을 부드럽게)

2·3주차에서 했던 것과 같습니다:

1. `ActionTest` 씬을 엽니다
2. 캐릭터를 선택 → `Inspector`에서 해당 동작 배열의 **오른쪽 끝 숫자**(장수)를 바꾸거나 **`+` / `−`** 로 칸을 늘림 → 새 파일 드래그 ([주인공 편 "배열을 다루는 법"](W02_플레이어_캐릭터_인스팩터.md))
3. ★ **판정 프레임 숫자를 반드시 다시 확인** (`Attack1 Damage Frame`, `Attack1 Effect Start Frame`, 몬스터C `Attack1 Projectile Frame` 등)
4. 플레이어: `Apply All Player Action Settings` → `Tools > Class Template > Sync Player & HUD From ActionTest`
5. 몬스터: `Apply Monster ○ Settings To Prefab`
6. **Ctrl+S**

> ⚠️ **완성 단계에서 프레임을 늘리다가 공격이 안 나가게 되는 사고가 매년 나옵니다.** 프레임을 늘렸으면 반드시 **Play해서 실제로 몬스터가 맞는지** 확인하세요. Console에 경고가 뜨는지도 같이 보세요.

## 6. 확인하기

### 완성본을 확인하는 순서

1. **`ActionTest` 씬** - 동작 하나하나, 판정이 정상인지
2. **`MonsterA/B/C_ActionTest` 씬** - 몬스터 동작 검사
3. **`BackgroundTest` 씬** - ★ **실제 게임 화면에서 배경과 함께** 어떻게 보이는지
4. 여유가 되면 **PC 빌드를 다시 만들어** 실제 화면에서 확인

| 확인 항목 | |
|---|---|
| 게임 화면에서 캐릭터가 배경과 분리되어 보이나 | |
| 동작이 부드럽나, 프레임 간 색이 튀지 않나 | |
| 공격 이펙트가 타격 순간에 맞춰 나오나 | |
| 이펙트 크기가 적당한가 | 너무 커서 화면을 덮지 않는지 |
| 몬스터 3종이 서로 구분되나 | |
| **공격이 여전히 정상적으로 맞나** | 프레임을 바꿨다면 필수 |
| 캐릭터가 바닥에 정확히 서 있나 | 채색하면서 기준점이 틀어지지 않았는지 |

## 과제 (12주차)

### 무엇을 해오나

**기존 러프 컨셉을 토대로 캐릭터·몬스터·이펙트를 완성·보완**

- **다 못 해도 됩니다.** 이번 주는 진행 상황을 확인하는 주차입니다

### 제출

네이버 카페 업로드 - 제목 `2D게임제작_12주차_123456홍길동`

- [ ] **진행본 영상**

- [ ] 게임 화면(1920x1080)에서 봤을 때 형태가 읽히는가
